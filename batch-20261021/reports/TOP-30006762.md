# Carry-free cubing counts distinct-element 3SUM exactly

Problem: TOP-30006762  
Claim type: Partial result  
Author: /root/hundred_algorithms

**Exact scope.** For distinct integers S⊆[−U,U], exact 3SUM decision and the number of unordered distinct zero-sum triples are computable deterministically in O((n+U+1) log²(n+U+2)) bit time using fast integer multiplication. This is subquadratic for U=O(n^(2−ε)), for fixed ε>0; it does not handle the prompt’s U=n³ worst case.

For n<3 return zero. Otherwise choose b=⌈log₂(n³+1)⌉ and β=2ᵇ. Encode the input by F=Σ(a∈S)β^(a+U) and extract
\[
 C=\lfloor F^3/\beta^{3U}\rfloor\bmod\beta.
\]
Every coefficient of the formal cube (Σx^(a+U))³ is at most n³<β. There are no carries between base-β digits, so C is exactly the number of ordered triples in S³ whose sum is zero.

The coefficient includes repeated entries, whereas the literal prompt requires three distinct elements. Put R=|{a∈S:−2a∈S}| and z=1 if 0∈S, and 0 otherwise. Each of the three equality events a=b, a=c, b=c contributes exactly R ordered zero triples. Every intersection of two equality events, and the intersection of all three, is the singleton (0,0,0) if z=1. Inclusion–exclusion therefore gives
\[
 D=C-3R+2z.
\]
It is the number of ordered triples with distinct entries. Thus D≥0, D is divisible by six, and D/6 is the exact unordered count. This handles the repeated pattern (a,a,−2a), the zero triple, and all small-cardinality boundaries. A multiset would require a different correction.

To compute R deterministically, sort the input and merge S with its sorted negative-double list. Build the packed binary representation by emitting the occupied digit positions in sorted order. The packed integer and its cube have O((U+1)log(n+2)) bits. Cubing costs two multiplications at constant multiples of that length. Harvey–van der Hoeven’s published theorem [1] gives O(K log K) bit operations for multiplying K-bit integers on a multitape machine. Sorting and dense packing cost O(n log n log(U+2)+(U+1)log(n+2)) bit operations. Since distinctness implies n≤2U+1, all terms fit the stated conservative bound. Outputting the O(log(n+2))-bit count is included. Space can conservatively be bounded by the same quantity as time; linear-space fast multiplication is not assumed.

In the standard logarithmic-word RAM, simulating each bit operation costs at most a constant number of word operations. When U=O(n^(2−ε)), logarithmic factors can be absorbed into any smaller fixed exponent saving. At U=n³, however, the method instead costs O(n³ polylog n). No subquadratic worst-case algorithm for the prompt is obtained. Large integer multiplication and allocating the dense universe are fully charged.

The preceding manuscript’s proposed StreamConv reporter has a stronger, unproved prefix-output requirement. Counting a single coefficient does not implement that reporter. Conversely this restricted-universe counting algorithm has no missing reporting hypothesis. An optional quadratic witness search is unnecessary for decision and is not included in the faster bound.

[1] D. Harvey and J. van der Hoeven, Integer multiplication in time O(n log n), Annals of Mathematics 193 (2021), 563–617, https://annals.math.princeton.edu/2021/193-2/p04 .
